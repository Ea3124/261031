# 앱 검증

현재 파일은 앱이 아직 없는 키트의 진입 지침이다. 새 과제를 맡은 에이전트는 소스를 읽고 아래 다섯 항목을 실제 명령과 결과로 교체한다. 존재하지 않는 명령이나 예시를 성공한 절차로 남기지 않는다.

## 실행

앱의 사용자 인터페이스, 정확한 시작 명령, 초기 데이터와 권한, 실행 위치를 적는다. 서버의 바인딩은 RULE.md를 따른다. CLI·파일 앱이면 새 임시 데이터에서 명령을 실행한다.

## 준비 확인

검증할 앱과 버전·초기 상태가 맞는지 확인한다. 공통 환경 점검 명령은 verification/project.json의 doctor이며, 실행 중 서버의 준비 확인은 runtime harness 안에서 수행한다.

## 조작

features의 기능별 진입·행동·기대 결과와 등록된 runtime 검사를 연결한다. 사용자 입력에서 저장·재조회까지 실행한다. 화면은 자동조작하지 않으며 응시자의 내부 Browser 확인과 프로그램 검사를 구분한다.

## 증거

공통 실행은 python3 kit.py check다. 각 앱 검사는 KIT_RUN_DIR에 입력·출력·부수효과를 남긴다. 결과는 .kit/runs/의 실제 보고서로 확인하고 python3 kit.py status로 현재 내용과의 일치를 확인한다.

## 정리

공통 실행기는 앱 명령 실행을 시작한 뒤 성공·실패 모두 cleanup을 호출한다. 설정·맵·stage·민감정보 사전검사에서 거절되어 앱 명령을 시작하지 않은 경우에는 호출하지 않는다. 앱 harness도 자신이 시작한 프로세스를 finally에서 종료한다. 임시 상태를 지우더라도 증거는 남아야 한다.

## 기능 맵

한 사용자 기능에 F ID 하나를 준다. map add → map sync → map check를 사용한다. 자세한 필드와 순서는 docs/fde/protocol.md를 따른다. 기능 맵은 소스 자체의 자동 요약이 아니며, 검사가 실제 사용자 결과를 확인하는지 읽고 실행한다.
