# 준비용 시나리오 1 — CLI 잔액 장부

키트 절차의 실제 검증용 합성 과제다. 이 문서 외의 구현·정답은 제공하지 않는다.

## 사용자 요구

Python CLI로 로컬 JSON 장부를 관리한다. 데이터 파일 경로는 명령 인자로 받는다. 입금·출금·잔액 조회가 가능해야 한다. 입력 금액은 양의 정수이며 통화의 최소 단위다.

같은 요청 ID를 같은 종류·금액으로 재실행하면 잔액을 두 번 바꾸지 않는다. 같은 요청 ID를 다른 내용으로 재사용하면 오류다. 잔액보다 큰 출금은 거절하고 저장된 잔액을 바꾸지 않는다. 잔액은 음수가 되지 않는다.

## 고정 인수 시나리오

1. 빈 임시 디렉터리에서 시작한다.
2. 요청 r1로 100을 입금하면 잔액이 100이다.
3. 요청 r2로 30을 출금하면 잔액이 70이다.
4. r2의 동일 출금을 반복해도 잔액은 70이다.
5. r2로 20 출금을 요청하면 실패하고 잔액은 70이다.
6. 새로운 요청으로 71을 출금하면 실패하고 잔액은 70이다.
7. 새 프로세스로 잔액을 조회해 70이 유지됨을 확인한다.
8. 0·음수·문자열 금액이 거절되고 파일이 오염되지 않음을 확인한다.

## 수행 계약

빈 독립 Git 프로젝트에 키트를 install한다. 실제 CLI를 만들고 사용자 인터페이스로 검사한다. 기능 맵은 최소 입금·출금·조회 3개를 작성한다. 실행·준비 확인·증거·정리 방법을 verify-app에 구체화한다.

정상 검증과 로컬 커밋을 수행한다. 이후 중복 요청을 두 번 반영하는 실제 회귀를 잠시 도입하고, stage 후 commit이 차단되며 HEAD가 유지됨을 확인한다. 원인을 수정하고 같은 작업단위에서 다시 커밋한다. 검사를 약화하지 않는다.

기능 맵의 깨진 검사 참조 또는 소스 참조도 한 번 탐지하고 복구한다. 코드 변경 뒤 status가 STALE인지 확인한다. 마지막에 인계 문서와 증거를 남긴다. 외부 전송·외부 AI·화면 조작은 하지 않는다.
