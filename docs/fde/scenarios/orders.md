# 준비용 시나리오 3 — CSV 주문 집계

키트 절차의 실제 검증용 합성 과제다.

## 사용자 요구

CSV를 읽어 확정 주문의 합계를 JSON 파일로 쓰는 CLI를 만든다. 컬럼은 order_id, amount, status다. amount는 정수 최소 통화 단위이며 음수가 아니어야 한다. status는 confirmed 또는 cancelled다.

같은 ID·금액·상태의 중복 행은 한 번만 센다. 같은 ID에 다른 금액이나 상태가 있으면 오류다. 잘못된 행이 하나라도 있으면 실패하며 기존 결과 파일을 변경하지 않는다. 출력은 결정론적이며 같은 입력을 다시 처리해도 같다.

## 고정 인수 시나리오

1. 임시 디렉터리에 입력을 만든다.
2. a,100,confirmed 행을 두 번, b,40,cancelled 행을 한 번, c,25,confirmed 행을 한 번 넣는다.
3. CLI로 처리하면 확정 주문 수는 2, 합계는 125다.
4. 새 프로세스로 같은 입력을 다시 처리해 출력 바이트가 동일한지 확인한다.
5. a의 금액이 다른 중복 행을 추가하면 실패하고 기존 결과 파일의 바이트가 유지된다.
6. 음수·숫자가 아닌 금액·알 수 없는 상태·필수 컬럼 누락이 거절되는지 확인한다.
7. 실패 전후 부분 출력이나 임시 파일이 남지 않는지 확인한다.

## 수행 계약

빈 독립 Git 프로젝트에 키트를 install한다. 기능 맵은 가져오기·중복 처리·결과 저장 3개 이상이다. 실제 CLI와 파일 결과를 검사하고 기대값 125는 요구사항에서 독립적으로 정한다.

정상 커밋 후 중복 행을 두 번 집계하는 실제 회귀를 잠시 도입한다. stage 후 커밋 차단과 HEAD 유지를 확인하고, 같은 단위에서 원인을 수정해 커밋한다. 기존 출력 보존 검사도 유지한다.

깨진 기능 맵 참조와 STALE 증거를 한 번씩 탐지하고 복구한다. 마지막에 인계 문서와 실제 입력·출력·실패·복구 증거를 남긴다.
