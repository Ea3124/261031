# 검증 범위와 보호 경계

## 무엇을 통제하는가

공통 실행기는 같은 명령·입력 환경·기능 맵 형식·증거 위치·종료 코드·커밋 조건을 제공한다. 설정 미완료, 검사 실패, 맵 불일치, 부분 stage, 검증 중 소스 변경, 오래된 증거를 성공으로 처리하지 않는다.

애플리케이션 자체의 결정론은 과제별 검증 코드가 만든다. 난수·시간·초기 데이터·외부 의존성을 고정하고 반복 실행 결과와 오류 경로를 확인해야 한다. 동일 명령이라는 이유만으로 모든 앱의 결과가 결정론적이라고 주장하지 않는다.

## 검사별 선택 기준

| 대상 | 기본 선택 | 추가 도구가 필요한 경우 |
|---|---|---|
| 문법·스타일·타입 | 해당 언어의 기존 컴파일러·검사기 | 프로젝트에 도구가 있거나 요구사항에 필요할 때 |
| 의존성 | 잠금 파일·사용 버전·기존 오프라인 검사 | 네트워크 허용·자료 범위 확인 후 공개 취약점 자료 조사 |
| 데이터·제어 흐름·오염 분석 | 입력 경계·권한·저장 경로·실제 공격 입력 검사 | 언어별 정적 분석기가 제공 환경에 있을 때 |
| 구조·아키텍처 | 경계·저장 계약·중복 상태·변경 영향 검토 | 구체적인 회귀 위험을 재현하는 스크립트가 있을 때 |
| 비밀정보 | 공통 패턴 검사와 diff 재독 | 실제 비밀 형식·개인정보는 프로젝트별 검사를 추가 |
| 비즈니스 불변식 | 실제 코드 대상의 단위·속성·통합 검사 | 동시성·재시도 등 고위험 속성은 범위를 정한 형식 검증 고려 |
| 성능 | 실제 요구 기준과 재현 입력·반복 측정 | 추적 기록·힙 등은 원인 조사에 필요할 때 |
| 화면 | 응시자가 플랫폼 내부 Browser에서 직접 확인 | 화면 자동조작 도구를 대체 경로로 연결하지 않음 |

기본 비밀정보 패턴 검사는 전수 탐지가 아니다. 정상 데이터가 민감정보인지 여부와 허용 범위는 과제 규칙과 직접 확인을 함께 따른다. 의존성 취약점 DB가 없는 오프라인 환경에서 “취약점 없음”이라고 보고하지 않는다.

## 증거 계약

각 실행은 .kit/runs/ 아래에 별도 폴더를 만든다. 명령 결과·출력·종료 코드·소요 시간·내용 지문·stage 트리 정보를 확인한다. 앱 검증 코드는 KIT_RUN_DIR에 입력·관측 결과·부수효과를 남긴다.

실패한 검사도 보고서와 로그를 남긴다. cleanup 뒤 증거가 남아 있어야 한다. 다음 실행으로 이전 실패를 덮어쓰지 않는다. 작업 내용이 바뀌면 과거 성공은 STALE이다.

로그에 문제 데이터 전체, 비밀 키, 개인 정보가 들어가지 않도록 앱 검증 코드를 작성한다. required_env 값의 마스킹은 보조 장치이며 모든 인코딩·변형을 탐지하지 않는다. 공개 평가 보고서는 준비용 합성 데이터만 포함한다.

## 격리와 프로세스

검증은 Git 루트에서 지정 argv로 실행한다. 추가 셸 해석을 하지 않는다. 검사에는 자기 실행 폴더를 제공하고 시간 제한을 적용한다. 프로세스 그룹 종료와 앱 harness의 finally 정리는 서로 보완한다.

이 실행기는 보안 샌드박스가 아니다. 등록한 명령은 현재 OS 계정의 권한을 가진다. 신뢰할 수 없는 코드를 실행하기 전 소스를 검토하고 실제 제공 환경의 샌드박스·권한 제한 안에서 실행한다. 훅이나 Python 검사를 보안 경계로 오인하지 않는다.

## 실전 UI의 확인 상태

CLI·HTTP·파일 검사를 수행했다면 그 범위를 명시한다. 화면 경로는 기능 맵에 사람이 수행할 조작 순서와 기대 결과를 기록하되 실제 확인 전에는 “미확인”으로 남긴다. 화면 확인이 완료 조건이면 사람의 관측 없이 전체 완료라고 보고하지 않는다.

## 형식 검증

불변식 테스트는 실행한 입력과 상태에 대한 증거다. 모든 상태에서 항상 성립한다는 형식 증명이 아니다. 형식 검증을 추가할 때는 속성·모델·가정·검증기 버전·명령·시간 한도·의도적으로 깨뜨린 반례 탐지를 기록한다. pstack의 형식 검증·statechart 자료는 비활성 원본으로만 제공하며 자동 설치나 실행은 하지 않는다.
