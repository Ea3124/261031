# 기능 맵

사용자 요청을 실제 기능과 실행 경로에 연결하는 구체적인 기억이다. 현재는 앱이 없는 초기 상태이며 기능·명령을 실행했다고 주장하지 않는다.

## 공통 실행·검증 절차
실제 문제의 버전·환경변수 이름·고정 데이터·초기 상태 복원·시작 명령과 인자·준비 신호·관찰 방법·시간 제한·정리를 기록한다.

같은 초기 상태에서 항상 이 절차로 실행한다. 공식 검증 입구는 ./scripts/check이며 실제 명령은 verification/check에 둔다. 새로운 세션도 같은 절차로 실제 상태를 확인한다.

## 사용자 기능
기능마다 목적, 진입점, 전제조건, 정확한 입력·동작, 기대 결과·상태 변화, 관련 소스, 검증 명령·증거를 작성한다.

UI·CLI·API·파일 처리·라이브러리·백그라운드 작업 모두 가능하다. 필요하면 불변식·권한·오류 입력·성능·주의사항·하위 기능을 추가한다. 자유로운 Markdown이며 Python 생성기나 고정 JSON 필드는 없다.

기능이 바뀌면 해당 설명과 관련 검사만 함께 갱신한다. 앱이 커지면 문서를 나누고 이 파일에서 연결한다. 구조적 파일 존재만으로 의미가 맞는다고 판단하지 않는다.

## 확인 상태와 제약
실제로 확인한 범위, 접근하지 못한 조건, 수동 화면 확인과 그 결과를 구분한다. API 성공을 화면 성공으로 대체하지 않는다. 제품 회귀를 설명이나 기대값만 고쳐 숨기지 않는다.
