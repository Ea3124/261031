# 단계별 선별 스킬

실제 실행을 단순하게 유지하면서 원본의 유효한 판단 기준을 놓치지 않도록 7개로 편집했다. 전부 매번 읽는 절차가 아니다. 시작은 fde-workflow 하나이며 해당 조건이 생길 때 관련 스킬을 읽는다.

| 스킬 | 읽을 시점 | 현실적으로 보강하는 부분 |
|---|---|---|
| [fde-workflow](../.agents/skills/fde-workflow/SKILL.md) | 시작·진행·마무리 | 사용자 기대 질문, 작은 변경→검증→증거 포함 커밋, 종료 경계 |
| [design-change](../.agents/skills/design-change/SKILL.md) | 기존 코드·설계·변경 영향이 불명확할 때 | 실제 호출 흐름·자료형·입력 경계·작업 분해·보안/데이터 파급 |
| [feature-map](../.agents/skills/feature-map/SKILL.md) | 기능 맵 생성·기능/사용법/제약 변경 | 사용자 관점의 구체적인 기억과 소스·검증 연결 |
| [verify-app](../.agents/skills/verify-app/SKILL.md) | 검증 구축·환경/방법 변경·검증 실행 | 동일 초기 상태·동일 방법·독립 기대값·실제 결과·증거·정리 |
| [test-verifier](../.agents/skills/test-verifier/SKILL.md) | 처음 검증 구축·핵심 로직/검증 변경 | 모든 핵심 로직별 결함주입 실패와 정상 복구 성공 |
| [debug-root-cause](../.agents/skills/debug-root-cause/SKILL.md) | 실패 원인이 불명확하거나 같은 오류가 반복될 때 | 같은 입력 재현·가설 확인·최초 원인 수정·회귀 |
| [handoff](../.agents/skills/handoff/SKILL.md) | 세션 전환·중단·완료·재개 | 실제 상태·증거·한계·다음 한 행동, 새 세션 실제 확인 |

## 한 작업을 처음부터 끝까지 따라가면

목표·기대 동작을 확인한다 → 필요할 때 기존 흐름과 변경 영향을 읽는다 → 작은 사용자 흐름을 구현하고 기능 맵을 적는다 → 고정 초기화·실행·검사를 만든다 → 핵심 로직을 하나씩 깨서 검증 실패·복구 성공을 확인한다 → 실패 원인을 고친다 → 세션 전환·완료라면 인계를 먼저 작성한다 → 최종 검증한다 → 코드·인계·증거를 함께 스테이징한다 → 커밋한다 → 실제 결과와 최종 SHA를 전달한다.

상세 원본 검토·채택/제외 이유는 [전체 선정표](skill-selection.md)에 있다. 원본은 고정 버전의 비활성 참고 자료이며 외부 모델·강제 위임·PR·화면 자동화·개인 설정·원격 로그 기능은 가져오지 않았다. 모델 SDK나 pstack 실행기를 설치할 필요가 없다.
