# HTTP 재고 예약 독립 E2E 평가

모델은 gpt-6-astra이며 부모의 실제 spawn 설정으로 확인했다. 소스 커밋은 c1045e32308fd292a01696406973e5912a442a9c다. git clone --no-hardlinks로 독립 복사하고 빈 Git 프로젝트에 실제 install했다. 원본 작업트리는 수정하지 않았다.

## 결과

정상 앱·독립 검사 세 종류·앱별 verify-app·기능 맵 세 개·의도/판단/인계를 직접 작성했다. 최초 정상 커밋은 c1c7967e162bd222f501ceadbf542f7177f7dd63, 회귀 복구 커밋은 46596ff5473464ae3f8a9d34e36e4c6e86c91563, 최종 인계 커밋은 1f93d15f67cbd5ae06e52c5a012c2d78d0114e0a다. 최종 Git 작업트리는 깨끗하고 검증 상태는 PASS다.

취소 표식 가드를 제거한 실제 회귀에서 HTTP 두 번째 취소의 재고가 기대1 대신2가 되었고 독립 원장은 기대2 대신3을 관측했다. 비즈니스·runtime 검사 모두 실패했고 git commit은 종료1, HEAD는 최초 정상 SHA 그대로였다. 실패 SHA는 생성되지 않았다. 같은 U002의 시도2/4에서 가드를 복구하여 커밋에 성공했다. 검사 코드나 기대값을 약화하지 않았다.

없는 검사 ID를 F003에 연결하여 map check와 전체 check 모두 종료1을 확인하고 정상 참조를 복구했다. 코드 변경 후 status의 STALE/1과 복구 후 PASS/0을 관측했다.

실제 서버는 0.0.0.0에 바인딩했다. 정상/실패/복구/인계 중 관측한 포트는 62690, 62730, 62779, 62793, 62848이다. 각 준비 JSON과 GET /health를 확인했고 localhost로만 요청했다. 다섯 서버 모두 자기 Popen 프로세스만 종료했으며 PID 부재·포트 폐쇄를 다시 확인했다. 실패 실행에서도 trace가 남았다. 화면 확인을 수행했다고 주장하지 않는다.

## 검증 범위

정적 검사는 Python 6개 파일의 AST/compile이다. 비즈니스 검사는 앱과 별도의 요구사항 원장을 사용해 1,296개 길이4 시퀀스, 5,184개 전이를 확인한다. 실제 HTTP 검사는 재고2 → r1 예약1 → 반복1 → ID 충돌 → r2 예약0 → 초과 거절 → 취소1 → 반복1 → 잘못된 값/JSON/없는 ID 뒤 상태 불변 → 취소 완료 ID 재시도 → 남은 취소 후 재고2를 확인한다. 단순 내부 함수 검사를 사용자 경로 확인으로 대체하지 않았다.

## 발견 사항

K01(낮음): kit.py doctor의 구성 통과가 앱 실행 환경 통과를 뜻하지 않는 점이 출력에서 구분되지 않는다. 제한 샌드박스에서 doctor는0을 반환했으나 check의 앱 doctor가 bind PermissionError로 실패했다. 전체 검증은 정확하게 차단한다. 출력 또는 문서에 구성 검사/실제 환경 검사 차이를 명시하면 오해를 줄일 수 있다. 원본 코드는 변경하지 않았다.

요구에 URL·JSON 필드·HTTP 상태 코드·취소 후 동일 ID 재실행·저장 방식이 지정되어 있지 않아 합리적인 앱 계약을 결정했고 work/decisions.tsv에 이유를 남겼다. 이는 공통 키트가 과제별 앱 구현을 맡기는 범위이며 차단 결함으로 분류하지 않는다.

초기 소켓 실패는 도구 환경 제한이며 승인된 로컬 서버 실행으로 해결했다. 최종 평가 스크립트는 설치 AGENTS에 추가된 표식을 처음에는 원본 변조로 잘못 판정했다. 설치기 동작을 읽고 표식만 차이임을 확인해 평가의 무결성 비교를 바로잡았다. 키트·앱 검증을 우회하거나 수정하지 않았다.

## 한계와 재현

화면·다중 동시 요청·부하 성능·형식 증명·영속 복구는 확인하지 않았다. 앱은 합성 ID r1/r2를 인수 경로로 사용하며 URL 구분자가 있는 임의 요청 ID의 취소 경로는 한계로 인계했다. 부분 stage 차단과 예산 한도 도달 자체를 별도 재현하지는 않았다. 정책상 외부 AI·전송·push·화면 자동조작을 수행하지 않았다.

실제 명령/종료코드는 .kit/evaluation/commands.jsonl, 정상·실패·복구 보고서는 .kit/runs, 서버 최종 감사는 .kit/evaluation/server-audit.json이다. 결과 JSON에는 소스만 읽고 이해한 12개 항목을 기록했다. 내보낸 예제의 README를 따라 키트 없이 검사하거나 빈 Git 프로젝트에 키트를 먼저 설치한 뒤 앱 파일을 복사하여 재현할 수 있다. vendor·개인 환경·.git·임시 시스템 파일·비밀값은 내보내지 않았다.

내보낸 디렉터리에서도 정적·원장·HTTP·정리 네 명령을 독립 실행하여 모두 종료0을 확인했다. 추가 서버의 실제 포트는62965, PID는48567이며 종료 뒤 PID 부재와 포트 폐쇄를 다시 확인했다. 증거는 evidence/export-check에 포함한다.
